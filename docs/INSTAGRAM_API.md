# 💬 Instagram API: директ и комментарии через официальный API

Подинструкция к [основной](GUIDE.md). Телефон умеет всё «руками», но отвечать в директ
и на комментарии надёжнее через **официальный API**: так работают сервисы автоответов,
Instagram не принимает это за бота, и всё работает, даже когда телефон выключен.

🎬 **Видео — те же шаги, где что нажимать:** _видео с этими же шагами — в Notion-версии инструкции_

---

## ✅ Что получится

- сервер читает директ и все комментарии твоего аккаунта;
- отвечает в директ и на комментарии (в течение 24 часов после сообщения человека — так устроен Instagram);
- видит статистику публикаций и может публиковать сам;
- ключ доступа (маркер) продлевается автоматически.

## 🧰 Что понадобится

- **Профессиональный аккаунт Instagram** (Автор или Бизнес), **открытый**.
- **Аккаунт Facebook** — через него входишь в кабинет разработчика Meta.
- Желательно **подтверждённое бизнес-портфолио** Meta. Если его нет — на последнем шаге
  Meta попросит подтвердить компанию документами (несколько дней).
- Сервер из [основной инструкции](GUIDE.md) (подойдёт любой компьютер с `curl`).
- ≈ 30 минут работы + несколько часов ожидания, пока Meta засчитает тестовые запросы.

## ⚠️ Какой именно API

Нужен **Instagram API with Instagram Login** (`graph.instagram.com`). В кабинете он
называется «Настройка API для входа в Instagram».

Вариант «…с входом через Facebook» для директа **не работает** — проверено вживую:
отправка отвечает `#230 Requires pages_messaging`, список диалогов висит до таймаута.
Если директ вдруг перестал работать — первым делом проверь, тем ли маркером ходишь.

## Часть 2. Права, тестировщик и маркер

### Шаг 8. Сценарии использования

Приложение создано. Слева — «Сценарии использования» → «Настроить».

![Шаг 8](img/api/08.png)


### Шаг 9. Добавь права

«Настройка API для входа в Instagram» → «Add all required permissions». Права: basic, comments, messages.

![Шаг 9](img/api/09.png)


### Шаг 10. Не перепутай!

«Настройка API для входа на Facebook» — другой вариант, для директа он не работает. Нам нужен только «…вход в Instagram».

![Шаг 10](img/api/10.png)


### Шаг 11. Добавь свой аккаунт

Шаг 2 «Сгенерируйте маркеры доступа» → «Добавить аккаунт».

![Шаг 11](img/api/11.png)


### Шаг 12. Профессиональный и открытый

Аккаунт должен быть профессиональным (Автор или Бизнес) и открытым — для закрытого маркер не выдадут. → «Продолжить».

![Шаг 12](img/api/12.png)


### Шаг 13. Назначь себя тестировщиком

Роль «Тестировщик Instagram» → впиши ник своего Instagram → «Добавить».

![Шаг 13](img/api/13.png)


### Шаг 14. Прими приглашение в Instagram

instagram.com → Настройки → «Приложения и сайты» → вкладка «Приглашения для тестировщиков» → «Принять». Появляется через минуту-две.

![Шаг 14](img/api/14.png)


### Шаг 15. Сгенерируй маркер

Вернись в кабинет: напротив аккаунта — «Сгенерировать маркер».

![Шаг 15](img/api/15.png)


### Шаг 16. Разреши доступ

Откроется окно Instagram: войди и нажми «Разрешить». Все переключатели оставь включёнными.

![Шаг 16](img/api/16.png)


### Шаг 17. Скопируй маркер

Отметь «Я понимаю» → «Копировать». Маркер показывают один раз. Никому не пересылай и не вставляй в чаты.

![Шаг 17](img/api/17.png)


### Шаг 18. Положи маркер на сервер

Файл с правами 600 — читать его можешь только ты. Ответ должен вернуть твой @ник.

```bash
cd ~/claude-phone-agent
umask 077; nano .ig-token        # вставь маркер, Ctrl+O, Enter, Ctrl+X

# проверка: должен вернуться твой ник
curl -s -H "Authorization: Bearer $(cat .ig-token)" \
  "https://graph.instagram.com/v26.0/me?fields=username"
```

## Часть 4. Публикуем приложение

*пока приложение не опубликовано, Meta прячет чужие сообщения и комментарии*


### Шаг 22. Настройки приложения → Основное

Политика конфиденциальности и удаление данных — ссылка на страницу GitHub Pages (не github.com/…/blob — её Meta не открывает). Иконка 1024×1024, категория. → «Сохранить изменения».

![Шаг 22](img/api/22.png)


### Шаг 23. Проверка → Тестирование

Строки «Необходимо выполнить 0 из 1» держат кнопку «Опубликовать». Нужен один успешный запрос к API по каждому праву.

![Шаг 23](img/api/23.png)


### Шаг 24. Сделай по запросу на каждое право

Последний запрос создаёт черновик публикации и ничего не публикует. Meta засчитывает запросы за несколько часов.

```bash
T="Authorization: Bearer $(cat .ig-token)"; G=https://graph.instagram.com/v26.0
curl -s -H "$T" "$G/me/insights?metric=reach&period=day"        # статистика
curl -s -H "$T" "$G/me/media?fields=id,comments_count&limit=3"   # публикации
curl -s -H "$T" "$G/ID_ПУБЛИКАЦИИ/comments"                      # комментарии
curl -s -X POST -H "$T" "$G/me/media" \
  --data-urlencode "image_url=https://…/любая-картинка.jpg"      # черновик
```


### Шаг 25. Тестирование выполнено

Через несколько часов строки станут «Выполнено». Строки «0 тестовых вызовов» ни на что не влияют — не удаляй права.

![Шаг 25](img/api/25.png)


### Шаг 26. Подтверждение компании

Если «Опубликовать» серая и просит подтвердить компанию: «Начать подтверждение» → выбери портфолио с пометкой «подтверждено». Нет такого — придётся пройти проверку с документами.

![Шаг 26](img/api/26.png)


### Шаг 27. «Недействительный URL»

Так Meta отвечает на ссылку github.com/…/blob/…: робот Facebook туда не пускают. Включи GitHub Pages и дай ссылку вида …github.io/…/PRIVACY.html.

![Шаг 27](img/api/27.png)


### Шаг 28. Опубликовано!

«Опубликовать» → «Ваше приложение опубликовано». Теперь API отдаёт директ и все комментарии.

![Шаг 28](img/api/28.png)


## Часть 5. Чтобы не сломалось через 60 дней

*маркер живёт 60 дней — продлеваем автоматически*


### Шаг 29. Автопродление маркера

Скрипт продлевает маркер раз в неделю, при сбое пишет тебе в Telegram. Сам маркер никогда не печатается.

```bash
cd ~/claude-phone-agent
.venv/bin/python ig_token.py check     # @ник и сколько дней осталось
.venv/bin/python ig_token.py refresh   # продлить на 60 дней

# cron: каждый понедельник в 04:40
( crontab -l; echo '40 4 * * 1 cd ~/claude-phone-agent && .venv/bin/python ig_token.py refresh >> .cache/ig-token.log 2>&1' ) | crontab -
```

| Что видишь | Почему | Что делать |
|---|---|---|
| Название приложения не принимают | в нём «ig», «insta», «fb» и т. п. | переименуй (шаг 3) |
| Приглашения тестировщика нет | приходит через 1–2 минуты и только в вебе | instagram.com → Настройки → «Приложения и сайты» → «Приглашения для тестировщиков». Аккаунт должен быть профессиональным и открытым |
| Директ и комментарии приходят пустыми: `"data": []`, но есть `paging.cursors` | приложение не опубликовано — Meta прячет данные людей без роли в приложении | Часть 4 |
| «Опубликовать» серая | не засчитаны тестовые запросы или не подтверждена компания | сделай по запросу на каждое право и подожди; выбери подтверждённое портфолио |
| «Недействительный URL политики конфиденциальности» | ссылку `github.com/…/blob/…` робот Facebook не открывает (ответ 503) | GitHub Pages: `https://ТВОЙ-НИК.github.io/…/PRIVACY.html` |
| `instagram_business_basic` «возвращается» после удаления | это базовое право сценария, без него ничего не работает | не удаляй; строки «0 тестовых вызовов» публикации не мешают |
| Через два месяца всё молча перестало работать | маркер живёт 60 дней | автопродление (Часть 5) |
| Хочу написать человеку первым | API так не умеет: писать можно только в ответ, в течение 24 часов | — |

### Где взять политику конфиденциальности

В репозитории уже есть шаблон — [`PRIVACY.md`](../PRIVACY.md). Сделай форк репозитория,

логотипов Instagram и Facebook.

## 🛡 Безопасность

- **Маркер = доступ к твоему директу.** Он живёт только в файле `.ig-token` с правами 600
  на сервере. Не вставляй его в чаты, документы и в git (`.ig-token*` уже в `.gitignore`).
- Засветился — выпусти новый: «Сгенерировать маркер» в кабинете. Полностью отозвать доступ:
  Instagram → Настройки → «Приложения и сайты» → твоё приложение → «Удалить».
- Политика конфиденциальности обещает удалять данные человека по его просьбе и хранить
  переписку не дольше 90 дней. Если строишь автоответчик — соблюдай это.
